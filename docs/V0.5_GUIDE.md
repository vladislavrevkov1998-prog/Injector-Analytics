# v0.5: отсчёт углов, дробный ввод и временная сессия

## Три исправления интерфейса

Числовые поля показывают значащие разряды без заполняющих нулей. После `0` можно сразу печатать `.125` или `,125`. При вставке цифры внутрь уже заполненной дробной части последний незначащий ноль удаляется автоматически; значащие цифры не отбрасываются. Шаг таблиц 0.001 и шкалы 0.0001 сохранён. Открытие и закрытие числового редактора без изменения не округляет исходные данные.

На вкладке 04 «Ось X эпюр» переключает градусы 0…360 и число окружных ячеек 0…N. Формула `x_ячеек=θ_в_системе_проекта·N/360`. При N=140 один шаг оси соответствует 360/140=2.571428571°. Точка 140 закрывает окружность и совпадает с 0; это не дополнительный замер. При ненулевом смещении первого центра координата в ячейках может быть дробной. Переключение не меняет расходы, поля или измерения. В split-проекте применяется та же система X для сопоставления физических углов; для таблиц можно явно выбрать абсолютные углы файла либо углы в системе проекта. Неугловые X (например время) не преобразуются. При изменении системы отсчёта угловые точки таблицы могут переупорядочиваться только в представлении, исходный файл сохраняется.

На вкладке 01:

- «Положение 0° от +X против ЧС» — физическое положение нового нуля на чертеже. Например 90° означает верхнюю точку окружности.
- «Направление увеличения угла» — обход гребёнки по/против часовой стрелки.
- «Смещение первого центра матрицы от нуля» — дополнительное смещение сетки относительно заданного нуля, обычно 0.

Внутренняя геометрия хранится в прежнем физическом отсчёте +X/против ЧС: `θ_global=θ_zero+s·θ`, где s=+1 против ЧС, s=−1 по ЧС. Изменение отсчёта не перемещает форсунки и не меняет их ID/измерения. Числа θ форсунок в таблице 02 переводятся в новый отсчёт; ручной ввод переводится обратно в физические координаты. Сетка привязывается к новому нулю/направлению, поэтому после такой настройки нужен F5. Местные 36 секторов форсунки и положительный Clock сохраняют собственный физический отсчёт против ЧС. Старые проекты получают ноль 0°, s=+1 и прежние результаты.

## Быстрый запуск v0.5

1. Откройте `examples/demo_project_v05_synthetic.json`. В нём **придуманные** давления, температуры, расходные характеристики, расходы и секторные объёмы; оставлены 140 позиций, включены три источника. Геометрический пример основан на пользовательском проекте, исходный пользовательский файл не меняется.
2. Перейдите на «05 · Измерительная сессия». Проект уже содержит сессию на 140 остановок × 6 одновременных каналов. Коллектор A содержит измеренный Δp, B — абсолютное давление топлива и отдельное абсолютное давление газа. Температуры сформированы независимо от топлива и не являются прогнозом.
3. Нажмите «Проверить», затем «Рассчитать сессию». Расчёт идёт в worker; есть отмена. Повторный расчёт с прежней геометрией использует кэш пространственных влияний.
4. В результатах доступны окружные эпюры топлива и измеренной T на отдельных Y, две составные матрицы, история давления и полный мгновенный снимок при выбранном t. Паспорт автоматически сворачивается, чтобы оставить место графикам; кнопка «Паспорт и параметры сессии» открывает его снова. Для эпюр работают прицел, точки, наклонные прямые, zoom и «Оси…». Составная матрица содержит разные временные окна, её нельзя считать одновременным полем.
5. «Отчёт CSV/XLSX» сохраняет результат вместе с окнами, координатами, площадками, давлениями, 140 расходами на остановку, балансами отдельных снимков и паспортом. CSV создаёт несколько файлов рядом. Экспорт относится к законченному расчётному снимку; после изменения входов нужно пересчитать.
6. «Сохранить сессию в проект» включает её в JSON проекта; затем Ctrl+S сохраняет файл. Включение отменяется/повторяется Undo/Redo и не изменяет статические поля. Можно сохранить отдельный JSON сессии. Незавершённый импорт и отменённый расчёт не заменяют предыдущий полный результат.

Расчёт без GUI:

```bash
python tools/run_session.py examples/demo_project_v05_synthetic.json --out report.xlsx
python tools/run_session.py examples/demo_project_user_field.json --session my_session.json --out report.csv
```

## Импорт своих данных

Вкладка 05 принимает отдельный JSON сессии или проект с `measurement_session`. Для CSV/XLSX выбирайте «Остановки»/«Давление», лист и сопоставление столбцов. Точных имён заголовков не требуется. Явно задайте единицы времени, давления, физический вид давления, коллектор и при необходимости сдвиг часов. Времена внутри приложения — секунды одной шкалы; сдвиг часов сохраняется отдельно от сырых времён.

Одна строка остановок содержит `step_id`, реальный угол (необязательно), t начала/конца, шесть T и их шесть флагов достоверности. Все шесть каналов имеют общее окно. Если конец окна отсутствует, импорт создаёт явно мгновенный замер; можно вместо этого задать длительность после timestamp. Пустая T остаётся пропуском. При отсутствии всех достоверных T проверка/расчёт сообщает об этом, нули не подставляются. Неполный обход допускается; `step_id` не является ID форсунки. Фактический угол используется вместо номинального; иначе `θ_i=θ_start+step_id·360/N`. Направление и ноль задаются в паспорте сессии.

Сессия хранит систему, в которой получены исходные углы, отдельно от текущей системы проекта. При загрузке другой сессии её паспорт не заменяется настройками вкладки 01. Изменять паспорт импортированного измерения нужно только при наличии такой информации об испытании. Радиусы R1…R6 соответствуют реальным датчикам в их порядке; совпадение с центрами расчётной сетки не требуется.

Давление содержит время, значение, коллектор, единицы, вид и достоверность:

- `delta_p` — уже измеренный перепад топлива относительно газа.
- `p_fuel_abs` требует `p_gas_abs` для того же коллектора или общего газа `*`.
- `p_fuel_gauge` требует `p_gas_gauge` с тем же непустым `reference_id` — общим нулём измерения.

Смешение абсолютного/избыточного базисов и отсутствие газа отклоняются. Поддержаны kgf/cm2 (кгс/см²), bar, Pa, kPa и MPa. Привязки форсунка→коллектор задаются на отдельной странице; пустая привязка использует видимый общий коллектор по умолчанию. Несуществующие ряды не подставляются. Времена давления должны строго возрастать внутри каждого канала; дубли/неотсортированные записи диагностируются. Разные коллекторы могут иметь разные сетки времени.

Временная экстраполяция и выход за диапазон Q(Δp) — разные разрешения. Первая задаётся на вкладке 05, вторая — настройкой испытательного режима на вкладке 02. По умолчанию обе запрещены. Физические ограничения Дитякина не отменяются флажком. Можно ограничить максимальный интервал между отсчётами давления; через недостоверные отсчёты интерполяция запрещена.

Сырые строки CSV/XLSX, их SHA256 и сопоставления сохраняются в метаданных; при подготовке JSON-сессии сохраняется исходный снимок сессии. Редактируются подготовленные копии. Исходные файлы и измерения не перезаписываются расчётом.

## Физический смысл и оценка

Для каждого источника сохраняется независимое геометрическое ядро K. Изменяется расход:

`q(P,z,t)=Σ_j G_j(t) K_j(P,z)`.

В режиме `curve` используется абсолютное Q(Δp) один раз. Для `manual/sectors` исходный расход при его опорном давлении умножается на `Q_type(Δp)/Q_type(Δp_ref)`. При отсутствии нужной характеристики расчёт сообщает о невозможности пересчёта, корневой закон автоматически не применяется. Нулевая опорная подача не используется как делитель пространственного ядра: единичные веса строятся независимо от G.

`q_corrected[r,i]` — средняя за окно плотность массового расхода по **консервативной ячейке, содержащей фактическую координату датчика**. Это не значение строго в математической точке и не footprint реальной термопары. В отчёте указаны настоящие радиус/угол, границы радиальной ячейки, её центр по углу и площадь. Для более мелких контрольных площадок увеличивайте разрешение сетки и проверяйте сходимость. Сектора делятся по ближайшему угловому центру; на радиальной границе выбирается внешняя соседняя полоса.

Усредняется Q(Δp(t)), а не Q от среднего давления. Давления интерполируются линейно. Для экспериментальных кусочно-линейных Q интеграл считается точно по трапециям с дополнительными точками пересечения узлов Q; для Дитякина — адаптивной квадратурой с заданным rtol. Min/max/mean Δp выводятся отдельно. У мгновенного измерения интеграл заменяется значением в timestamp.

Проверяйте покрытие временных окон, физический базис и диапазон давления, координаты/площадки и предупреждения. Сверяйте постоянный режим со статикой и баланс отдельных снимков `G=in+inner+outer`. Для матрицы из разных времён общего мгновенного баланса нет. Высокие/низкие значения топлива нельзя напрямую трактовать как высокую/низкую T: воздушная и температурная модели в v0.5 не введены, регрессия топлива к температуре не выполняется.

Задержка по умолчанию 0 — квазистационарное предположение. Можно задать независимую известную общую задержку, задержку форсунки и точечные добавки JSON `point_delays_s` с ключом `step_id:канал(1…6):nozzle_id`. Они суммируются; окно топлива сдвигается назад по времени. Скорости/время пролёта из геометрии не выдумываются. Мгновенные полные снимки и их баланс относятся к τ=0; результаты с разными точечными задержками не объявляются глобально одновременным полем. Инерция термопары хранится в метаданных отдельно и не корректируется.

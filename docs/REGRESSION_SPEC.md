# Регрессионный фундамент — спецификация для v0.4

Статус: проект интерфейсов и алгоритма. **Регрессия между топливной эпюрой и температурой не разрешена.** После будущей физической модели воздуха и температуры будет отдельный, пока не определённый прямой оператор `T_model(...)`; его нельзя имитировать нормировкой топлива.

## Что сопоставимо сейчас
- Топливное поле `q_f(x,y,z)` [кг/(м²·с)] с другим сопоставимым топливным полем на тех же физических координатах.
- Контрольная массовая нагрузка `G_cell` — только при одинаковых областях интегрирования.
- Нормированные эпюры `I=q/<q>` — только как отдельная безразмерная цель, с документированной областью среднего и маской нулевых средних.
- Тестовая цель, полученная из заведомо известных параметров генератора, обязательна для первого приёмочного теста.
- Таблица температур может отображаться в сравнительной панели v0.3.1, но **не передаётся оптимизатору v0.4 как y_target**.

## Предлагаемый интерфейс данных
`RegressionTarget`:
- `quantity`: `flux` / `cell_mass` / `normalized_ring` / `normalized_track`;
- `z_global_mm`, `radial_index` или `radius_mm`, `theta_deg[]`, `y[]`, `mask[]`, `weights[]`, единицы и метаданные;
- строгая валидация геометрического сопоставления; периодичность θ, направление отсчёта и угол нуля должны соответствовать физическим данным, а не просто индексам массивов.
`ParameterSpec`:
- ключ параметра, scope (nozzle_kind / nozzle ID), начальное значение, min/max, fixed/optimized, единицы; активность в выбранном `geometry_model`/`angular_model`;
- не допускать параметр, который не влияет на результат при данном z (например, коэффициент углового размытия при z=0).
`RegressionSnapshot`: неизменяемая глубокая копия всех исходных параметров, версии проекта и контрольной hash/serialization метки.
`FitResult`: новые значения, начальный/final cost, R²/MAE/RMSE, residual vectors, Jacobian rank/condition, active bounds, количество прямых вызовов, статус convergence/cancel, версия алгоритма и возможные предупреждения.

## Задача
Для поднабора `β` минимизировать
`J(β)=Σ_i w_i (f_i(β)-y_i)^2 + λ||S(β-β0)||²`, с box constraints и `λ>=0`.
- Для распределений с большим динамическим диапазоном отдельно выбирать критерий абсолютной или относительной ошибки (с контролем малых y); не смешивать его незаметно.
- По умолчанию группировать по типу форсунки (охлаждаемая/неохлаждаемая); число регулируемых параметров должно быть намного меньше числа независимых наблюдений. Индивидуальное варьирование параметров каждой из 140 форсунок не включать в пилотный fitting без отдельного решения.
- Регрессия не должна переписывать измеренные 36 `sector_ml`, расходные характеристики и неизменяемые экспериментальные данные.
- Выводить метрики отдельно по train и holdout/test наблюдениям. При `Σ(y−mean(y))²≈0` не определять R² как число (N/A).
- Производные, ранг и обусловленность — диагностические оценки, не автоматическое доказательство уникальности решения.
- Геометрические ограничения: положительная толщина; физически допустимые радиусы; отсутствие ненужных падений режима вне допустимого интервала z. Проверять кандидатов на всех используемых z.
- Нормировочные функции топлива — часть прямой модели; не изменять mass balance для улучшения критерия.

## UX
Окно «Идентификация параметров»:
1. выбрать топливный эталон (JSON, CSV/XLSX), сечение z, радиальный пояс, диапазон углов и определение целевой величины;
2. выбрать `geometry_model`, `angular_model` и параметры, scope, старт/bounds, regularization, лимит eval;
3. кнопки «Проверить входные данные», «Запустить», «Отменить», «Предпросмотр до/после», «Применить», «Отменить применение/Вернуть исходное»;
4. отображать остатки по углу, диаграмму качества и предупреждения.
Оптимизация запускается в worker, не блокирует Qt; прогресс и отмена безопасны. Результат применяется одной undoable операцией; до применения рабочий JSON не мутируется.
Экспорт XLSX: листы `Parameters` (scope, key, unit, initial, min,max,fitted, delta, bound-active), `Metrics`, `Residuals`, `Metadata`, `Validation`. Не скрывать неприменимость R².

## Acceptance и тестовые случаи
- Искусственная цель с известными α/k/Clock при достаточном числе z и неплоской эпюре; параметр восстановлен с численным допуском, holdout не хуже допустимого. Не требовать восстановить одновременно коррелирующие параметры с одной эпюры.
- Неправильный угол/радиус, недостаток независимых точек, постоянная цель и потеря физических ограничений дают объяснимый статус.
- Повторная оптимизация на одном seed и вводе воспроизводима, результат отменяем.
- Исходный JSON после rollback эквивалентен исходному; чужие пользовательские поля и legacy keys сохраняются.
- Секторные V, референсные Q(Δp), mass balance не меняются, кроме следствий **явно применённых** геометрических параметров.

# Подготовка v0.2

Основа — v0.1.3.dev0, принятая в main (`0338c9c`). Windows/Spyder по указанию
пользователя пока исключены из обязательных проверок. Это подготовительный
этап, а не выпуск полной v0.2.

## Выполнено

1. Превью одной форсунки: 400×400 вместо 240×240, 160 000 вместо 57 600
   отображаемых ячеек (**2,78 раза**). Полярная линия: 288 вместо 144 интервалов.
   Bilinear делает обычное изображение плавнее; в Manual/Clip to range остаётся
   nearest, чтобы не смешивать прозрачные области с видимыми. Это не меняет
   измеренные 36 объёмов, контрольную матрицу, полный расчёт или баланс.
2. `src/fuelfield/characteristics.py` — независимое ядро экспериментальной
   характеристики и переводов единиц, пока не включённое в GUI/физическую модель:
   - произвольное положительное число измеренных пар; давление кгс/см²,
     канонический расход кг/ч;
   - конечные значения, Δp > 0, Q ≥ 0, уникальные давления, сортировка копии;
   - неизменяемые точки; точное возвращение измерений; кусочно-линейная
     интерполяция без сглаживания, включая немонотонные измеренные расходы;
   - экстраполяция по умолчанию запрещена; при явном разрешении — предупреждение
     и `extrapolated=True`; отрицательные оценки отклоняются без обрезания;
   - одна точка допустима для хранения, но не создаёт выдуманную зависимость;
   - кг/ч ↔ л/мин при заданной плотности; standalone JSON с явными единицами.
3. Добавлены тесты этих правил, включая известную характеристику с отношением
   Q(30)/Q(2.5)=12. Сам пересчёт физических режимов в текущем приложении ещё
   не включён, независимые измеренные расходы не перезаписываются.

Standalone-формат характеристики **не объявляется новой схемой проекта**:

```json
{
  "kind": "experimental",
  "pressure_unit": "kgf/cm2",
  "flow_unit": "kg/h",
  "points": [[2.5, 2.0], [30.0, 24.0]]
}
```

## Последовательность реализации

| Этап | Работа | Критерий приёмки |
|---|---|---|
| A — экспериментальный справочник | Каталог типов на первой вкладке; ID/имя; редактор точек, график, добавление/удаление, CSV/XLSX; atomizer_type_id у форсунок | Несколько типов; запрет удаления используемого типа; импорт валидируется атомарно; точки графика точно совпадают с измерениями; Undo/Redo включает весь каталог |
| B — режимы и единицы | Отдельное давление измеренного расхода, давление секторов, целевое давление, полнота сбора; кг/ч ↔ л/мин в таблице; видимый источник оценки | Пересчёт по известной кривой; предупреждения об экстраполяции и неизвестной η; ручное измерение при 30 и исходные сектора неизменны; смена единиц не меняет массу |
| C — геометрия и типы | Охлаждаемая/неохлаждаемая, редактируемые шаблоны и overrides/reset; наружный радиус плёнки R_сопла | Миграция R_сопла=Rc0+h0/2 сохраняет Rc0 и старые поля; смена шаблона не уничтожает overrides/измерения |
| D — расстановка | Manual и auto-follow, перемещение текущей и последующих только в её ряду | Второй ряд и предшествующие позиции неизменны; отключённые позиции не исчезают и не сдвигают соседей |
| E — расчётная характеристика | Верифицированная методика Дитякина, после согласования формул и применимости | Уравнения и коэффициенты привязаны к источникам; независимые контрольные примеры и размерностные проверки; согласованная методика до включения в UI |

Этап A — следующий пользовательский функциональный шаг. B–D можно выполнять
независимо от E. Каждый этап: исходные тесты → реализация → регрессии → проверка
GUI offscreen и массового баланса → отдельный коммит/отчёт.

## Совместимость и физические ограничения

- Загруженный проект v0.1.0–v0.1.3 должен сохранять прежние расчётные результаты
  до явного выбора новых характеристик/режимов. Добавление давления 30 в
  метаданные **не должно автоматически масштабировать старый sectors-расход**.
- На первом этапе ссылки на тип опциональны для legacy-проектов. Каталог,
  ссылки и настройки входят в один сериализуемый snapshot Undo/Redo.
  Миграция схемы проекта и контрольные JSON-fixtures нужны до включения каталога.
- В новых режимах измерение расхода при 30 кгс/см² хранится независимо от
  секторных измерений при 2,5 кгс/см²; оценка имеет отдельные источник и статус.
- Для sectors: ṁ₂․₅ = ρΣV·10⁻⁶/(Tη), затем множитель Q(target)/Q(2.5).
  При неизвестной η допускается только явно обозначенное допущение η=1.
  Нулевая Q(2.5), отсутствующая характеристика или неподтверждённая экстраполяция
  не должны приводить к скрытому пересчёту.
- Переключение отображаемых единиц использует каноническое значение кг/ч;
  повторное переключение не округляет хранимые данные.
- R_сопла и h0 определяют Rc0=R_сопла−h0/2; старые файлы мигрируются по
  R_сопла=old_Rc0+h0/2. Численный эквивалент тестируется на всех четырёх z.
- q — плотность массового расхода, не концентрация. Баланс включает выход
  за обе стенки. Контрольная матрица по умолчанию остаётся 6×140.

## Верификация методики Дитякина

Предоставленные в дорожной карте источники пока **не верифицированы**:

- https://journals.ssau.ru/vestnik/article/download/8927/8330
- https://ingc.ru/upload/iblock/255/kafgqmdqmwfredrjxdr0t3d7ev60hiy0.pdf

До реализации требуется ведомость «уравнение → страница/номер → обозначения
и единицы → коэффициенты → область применимости → контрольный пример».
Проверить геометрию камеры/сопла/тангенциальных каналов, коэффициенты и систему
единиц давления, расхода и плотности; зафиксировать процедуру решения и
неоднозначности. Если источники расходятся, сначала согласовать выбранную
методику. Формула μA√(2ρΔp) не реализована и не выдаётся за метод Дитякина;
Тейлор не включён в интерфейс.

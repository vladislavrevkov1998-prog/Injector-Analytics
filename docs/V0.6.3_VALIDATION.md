## Причины замечаний и исправления

| Случай | Причина и результат |
|---|---|
| Готовые стенки до S5=160, старый выход S4=60 | Продолжение искало участок, заканчивающийся строго на старом выходе. Уже нарисованное продолжение мешало согласованию. Теперь учитывается фактический конец каждой непрерывной стенки: совпадающий с новым выходом профиль сохраняется без изменений; достраивается только недостающая часть. Старый выход согласуется с max(z) при применении черновика. |
| «Дуга поворачивает по z» | Значительный разворот действительно делает R(z) многозначным, но прежний угловой допуск не учитывал размер дуги. Теперь допуск связан с физической погрешностью положения концов. Большая дуга вместо малой явно исправляется кнопкой направления, без изменения концов/центра/радиуса. Настоящие петли не принимаются. |
| Сечение выше нарисованного тракта | При ошибке Chamber использовались радиусы старого цилиндра. Теперь берутся фактические пересечения с нарисованными стенками. Неоднозначное/отсутствующее пересечение скрывает линию, не подставляет старый размер. |
| Совпадение мешало касательности | Выбор по двум перекрывающимся маркерам не позволял попасть во второй. Теперь выбираются тела кривых; существующая цепочка совпадений имеет приоритет при определении контакта. Неоднозначный случай уточняется концами в диалоге. |
| Касательность дуга–дуга | Точное решение окружности через противоположный конец и нормаль опорной дуги в контакте. Первая дуга подгоняется ко второй; фиксация учитывается. Опорная геометрия сохраняется; порядок зависимостей решается явно, несовместимые циклы диагностируются. |
| Undo пропускал черновик и его сброс | В историю входили только принятые проекты. Теперь команда хранит отдельно применённый проект и видимый черновик/ошибочный текст. Один ввод, вставка или жест — один шаг. Undo сброса возвращает созданный эскиз, не передавая некорректную геометрию расчёту. |

Скриншот не содержит точных координат/JSON исходного пользовательского эскиза.
Для воспроизведения создан отдельный **синтетический** S-профиль с двумя
стенками, входными дугами, парными сопряжёнными дугами и выходом 160 мм:
[пример](../examples/demo_project_v063_s_profile.json),
[воспроизводимый генератор](../tools/create_v063_example.py),
[снимок UI](images/v0.6.3/s-profile.png). Проверка намеренно выставляет ему
старый выход 60 мм и подтверждает принятие **без изменения примитивов**.

## Проверки

Linux, Python 3.12, PyQt5 offscreen. Windows/Spyder не проверялись согласно
ранее заданному ограничению. Baseline на `d7794ab`: **64 теста v0.6.2,
61,543 с, OK**. Независимые аудиты математики, UI и миграций выполнены.

Полный прогон основной реализации: **442 теста, 273,245 с, OK, без пропусков**.
Затем закрыт дополнительный случай сохранения ошибочного текста при правке
другой строки: **12 проверок истории, 9,438 с, OK**. Заключительный полный
прогон после этой защиты: **445 тестов, 296,176 с, OK, без пропусков**.

Новые проверки охватывают точную касательность в мм/см/м, внутреннее/внешнее
касание окружностей, опорную и две фиксированные дуги, зависимые цепочки и
циклы, контакт через совпадение, неоднозначность контакта, малую физическую
погрешность и реальный разворот. UI проверяется настоящими нажатиями мыши по
телам кривых и Ctrl+Z/Ctrl+Y, восстановлением ошибочного текста, сброса и
скрытого эскиза, неизменностью снимков истории и отсутствием повторной
перестройки таблиц. Проверяется чистый TXT-перенос и загрузка встроенных картинок
инструкции без репозитория и папки docs.
Ошибочная ячейка блокирует применение всего черновика до исправления/сброса;
ошибки привязаны к ID, не переходят на соседний объект после удаления строки.
Проверен возврат к исходному числу настоящим числовым редактором.

Отдельно рассчитаны все пять сечений синтетического S-профиля, матрицы 6×140:
максимальный модуль относительной ошибки мгновенного массового баланса
`5,36·10⁻¹⁶`. В узком выходном канале большая доля попадает в wall-bound —
это локальная классификация исходного факела, не перенормированный поток.

Геометрия остаётся schema 2, формат проекта прежний. Старые arc–line связи,
schema 1 и неизвестные поля сохраняются. v0.6.2 явно отклоняет новую пару
arc–arc, не теряет её молча. История Undo существует в памяти сеанса; сохранение
JSON по-прежнему включает только принятый проект.

## Инструкция и физические границы

[Инструкция](V0.6_GUIDE.md) содержит три схемы: действующий независимый расчёт
сечений и учебные сужение/расширение с сеткой, стрелками всех трёх поясов и
численными долями пересечения кольцевых площадей. Учебные доли явно обусловлены
прямыми осевыми лучами и q=const; это **не реализованная транспортная матрица**.
Действующее ядро заново рассчитывает координаты и веса эмпирического факела
для каждого z; одинаковые индексы квадратуры не являются сохраняющимися
частицами. История удара, плёнка и перенос вдоль стенки остаются вне v0.6.
Схемы встроены в runtime-справку TXT как кодированные изображения; отдельных
папок docs/examples/проектов в переносимом архиве нет.
[Снимок открытой инструкции Qt](images/v0.6.3/instructions.png) подтверждает,
что схемы отображаются в справке, а не только присутствуют в файлах.

Готовый `txt/Fuel_Field_Pilot_0.6.3_IDLE_TXT.zip` дополнительно восстановлен
из самого ZIP в отдельную папку с кириллицей, без Git/docs/examples. Все
runtime-исходники побайтно совпадают с commit
`42fb9d4c2d42951d6ed4cc4d44fde73b9951f19e`; запускаются UI, дуга–дуга,
Undo сброса и все три справки с тремя изображениями. Результат `ARCHIVE_UI_OK`.
Размер 390832 байта; SHA-256
`d06934c90aa43dfd1b7839d5b344059561a835c0470650a5e6e7c299a07fa13a`.

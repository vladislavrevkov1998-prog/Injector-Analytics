# Вкладка 05 «Измерительная сессия»: подробная инструкция

Список **«Раздел»** вверху окна позволяет сразу перейти к нужной таблице,
параметрам, результатам или сохранению. Окно можно оставить открытым рядом
с вкладкой и обращаться к нему во время заполнения.

## 1. Для чего нужна сессия и куда попадает результат

Вкладка сопоставляет последовательный температурный обход с расчётным топливным полем при изменяющемся давлении. На одной окружной остановке одновременно измеряются **шесть температур на шести радиусах**. Следующая остановка имеет своё время и, возможно, другое давление.

**После «Рассчитать сессию» результаты появляются только на странице «Результаты» вкладки 05. Автоматически в основной расчёт вкладки 04 они не передаются. Расходы, секторные объёмы, геометрия форсунок и коэффициенты проекта расчётом сессии не изменяются.**

Связь направлена от проекта к сессии: вкладка 05 использует геометрию/сетку, включённые форсунки, типы, модели и расходные характеристики вкладок 01–03. По временным давлениям она отдельно вычисляет расходы и топливный поток в координатах датчиков. Температура остаётся исходным измерением. Она не пересчитывается в топливо, не обучает модель и не используется для идентификации параметров.

«Сохранить сессию в проект» включает **входной протокол и настройки сессии** в JSON проекта, но не применяет вычисленные расходы к форсункам. Рассчитанные массивы сохраняются через «Отчёт CSV / XLSX»; после повторного открытия JSON сессию нужно рассчитать заново.

## 2. С чего начать

1. Откройте свой основной проект через меню «Проект». Проверьте размеры и сетку на 01, включённые форсунки/источники расхода на 02, модели на 03 и расходные характеристики типов. Основной расчёт F5 заранее выполнять необязательно.
2. Откройте вкладку 05. Разверните «Паспорт и параметры сессии». Начальные радиусы/z/отсчёт могут быть скопированы из проекта — замените их фактическими данными вашего испытания.
3. Заполните паспорт, импортируйте остановки и давление либо введите их вручную. Проверьте коллекторы и часы приборов.
4. Нажмите «Проверить», исправьте сообщения, затем «Рассчитать сессию».
5. Изучите пять представлений результатов. Сохраните отчёт; для повторной работы сохраните входную сессию отдельно или включите её в проект и нажмите Ctrl+S.

Для знакомства можно открыть `examples/demo_project_v05_synthetic.json` через меню «Проект». Он уже содержит заполненную сессию. Все давления, T, расходы и сектора этого примера **синтетические**, это не данные испытаний. `examples/demo_project_user_field.json` остаётся исходным пользовательским проектом; температурный протокол и временные давления в него сами не добавляются.

## 3. Верхние кнопки

| Кнопка | Действие |
|---|---|
| **JSON сессии / проекта** | Загружает входную сессию из отдельного JSON или из поля `measurement_session` другого проекта. Из другого проекта извлекается только сессия; его геометрия и форсунки не заменяют текущий основной проект. Для открытия всего проекта используйте меню «Проект». Загруженная сессия заменяет текущие таблицы вкладки 05 и очищает её прошлый результат. |
| **Остановки CSV/XLSX** | Читает лист протокола и открывает выбор столбцов. Успешный импорт заменяет всю таблицу остановок, а не дописывает строки. |
| **Давление CSV/XLSX** | Импортирует давление топлива и/или газа. Заменяет имеющиеся строки для совпадающих сочетаний «коллектор + вид давления», оставляя остальные каналы. Можно последовательно загрузить топливо A, топливо B и газ. |
| **JSON: сохранить** | Сохраняет текущие входы вкладки 05 в отдельный файл сессии. Не сохраняет полный основной проект или рассчитанные поля. Поля должны читаться как корректные данные. |
| **Инструкция** | Открывает это отдельное окно. Его можно оставить рядом с приложением; оно не блокирует редактирование или worker расчёта. |

## 4. Паспорт измерения: каждое поле

| Поле | Что заполнить |
|---|---|
| **z измерения, мм** | Глобальную осевую координату плоскости сопоставления в той же системе z, что и проект. Это не расстояние от среза каждой форсунки: её `z_tip` учитывается отдельно. Можно задать z, которого нет в списке сечений вкладки 01. |
| **Радиусы R1…R6, мм (через ;)** | Ровно шесть различных фактических радиусов датчиков, строго между внутренней и наружной стенками тракта. Порядок соответствует T_R1…T_R6. Например, только для демонстрации: `275; 305; 335; 365; 395; 425`. Совпадение с центрами расчётной сетки не требуется; не заменяйте реальные радиусы центрами ради удобства. |
| **Ноль сессии от +X против ЧС, °** | Физическое положение нуля, относительно которого записаны углы измерений. Значение 0 — ось +X, 90 — ось +Y на чертеже. Сам угол положения нуля всегда откладывается против часовой стрелки от +X. |
| **Направление обхода** | Направление увеличения угла в записи измерительной гребёнки: против часовой стрелки или по часовой стрелке. |
| **Первый номинальный угол сессии, °** | Угол остановки с `step_id=0` в системе сессии. Нужен для строк с пустым «θ сессии». Не добавляется повторно к явно введённому углу строки. |
| **Номинальных положений в окружности** | Число равных шагов полного обхода, обычно 140. Это не число импортированных строк. Если измерены лишь 20 положений из 140, здесь всё равно 140. Шаг = 360/N градусов. |

Перевод угла сессии в физический угол: `θ_global = (θ_zero + s·θ_session) mod 360`, где s=+1 против ЧС, s=−1 по ЧС. Для пустого угла строки: `θ_session = (θ_start + step_id·360/N) mod 360`.

Пример **только для объяснения координат**: ноль=90°, направление по ЧС, θ_start=0°, N=140. Тогда step_id=0 соответствует физическим 90°, step_id=1 — 87.428571°. Это не перемещает форсунки.

Паспорт загруженной сессии описывает отсчёт исходного испытания и хранится отдельно от текущего отсчёта проекта на вкладке 01. Изменение 01 не переписывает старые измеренные углы. Исправляйте паспорт только при наличии сведений об отсчёте записи. Графики результатов переводятся в отсчёт проекта, сохранённый в расчётном снимке.

Геометрическая модель топлива применяется при заданном z. Её область — топливо за ФУ до дополнительного подвода воздуха; температурные датчики на выходе КС не превращают эту модель в модель температуры или горения.

## 5. Время и давление: каждое поле

| Поле | Что заполнить |
|---|---|
| **Коллектор по умолчанию** | Имя общего канала давления, например `A`. Его используют форсунки с пустой индивидуальной привязкой. Такое имя должно существовать в таблице давления. Регистр и написание должны совпадать. |
| **Заданная транспортная задержка τ, с** | Независимо известную общую задержку переноса топлива. Неотрицательное число; если задержка не известна, оставьте 0. Тогда предполагается мгновенное следование поля за давлением, а не доказанное отсутствие времени пролёта. |
| **Макс. разрыв давления, с (0 = не ограничен)** | Максимальный допустимый промежуток между двумя соседними отсчётами давления, между которыми проводится интерполяция. Например, 0.5 запрещает интерполировать внутри интервала длиной 2 с. Ноль снимает это ограничение, но не разрешает проходить через недостоверные отсчёты или выходить за запись без соответствующего флага. |
| **Относительная точность Q-интеграла** | Численную точность усреднения расхода для адаптивного интегрирования Дитякина, обычно `0.000001` (1e-6). Допустимо 1e-10…1e-2. Меньше — строже вычисление, потенциально дольше расчёт. Это не точность датчика и не погрешность физической модели. Для экспериментальной кусочно-линейной Q используются точные трапеции с разбиением по её узлам. |
| **Разрешить временную экстраполяцию** | Оставляйте выключенным при обычной обработке. При включении вне диапазона записи линейно продолжается первый/последний интервал давления; использование отражается в предупреждениях отчёта. Это не восстановление отсутствующих измерений. |
| **Экстраполяция Q(Δp)** | Информационная надпись, не поле ввода. Разрешение выхода за измеренный диапазон расходной характеристики меняется через шестерёнку настроек вкладки 02. Оно независимо от временной экстраполяции. Физические границы применимости Дитякина не отменяются флажком. |

При задержке τ окно топлива сдвигается назад: для измерения в [10,11) с и τ=0.2 с используется давление на [9.8,10.8) с. Проверьте наличие этой части записи. Общая задержка и задержка форсунки суммируются. Отклик термопары — отдельный механизм; приложение не исправляет его автоматически.

## 6. Таблица «Остановки: 6 каналов»: каждая ячейка

**Одна строка — одна остановка и одно общее временное окно для всех шести каналов.** Числа вводятся без приписанных единиц. Десятичная точка и запятая поддерживаются.

| Столбец | Что вводить |
|---|---|
| **step_id** | Уникальный неотрицательный целый индекс измерения. Обычно 0…139. Это **не ID форсунки**. При пустом угле именно этот индекс участвует в формуле номинального положения; для первой остановки используйте 0, а не 1. При неполном обходе можно сохранить исходные индексы. |
| **θ сессии, °** | Фактический измеренный угол в системе паспорта. Можно оставить пустым, если известны θ_start и N и допустим расчёт номинального угла по step_id. Явный угол имеет приоритет. Одинаковые углы в разные времена допустимы при разных step_id. |
| **t начала, с** | Начало окна одновременного считывания шести T, в секундах общей шкалы времени. |
| **t конца, с** | Конец того же окна. Для усреднения должен быть больше начала. Окна разных последовательных остановок не должны перекрываться; соседние границы могут совпадать. Времена движения гребёнки между остановками не обязаны входить в окна. |
| **Метод** | `window` для обычного окна усреднения. `instantaneous` для явно мгновенного отсчёта, при котором начало и конец равны. `explicit_duration` устанавливается импортом timestamp с заданной длительностью и также означает усреднение по окну. Запись слова `instantaneous` сама не меняет времена — при ручном вводе задайте их равными. |
| **T_R1, °C** | Температуру датчика на первом радиусе из паспорта. При отсутствии измерения — пустую ячейку и снятый valid R1. |
| **T_R2, °C** | Температуру на втором радиусе; та же политика пропуска. |
| **T_R3, °C** | Температуру на третьем радиусе; та же политика пропуска. |
| **T_R4, °C** | Температуру на четвёртом радиусе; та же политика пропуска. |
| **T_R5, °C** | Температуру на пятом радиусе; та же политика пропуска. |
| **T_R6, °C** | Температуру на шестом радиусе; та же политика пропуска. |
| **valid R1…valid R6** | Шесть отдельных флажков достоверности соответствующих T. Установленный флаг требует числовой T. Снятый исключает её из графика T и температурной матрицы, но сохраняет введённое число в исходных данных и отчёте. Он не выключает форсунку или расчёт топлива в этой координате. |
| **Примечание** | Необязательный комментарий к остановке: неисправность датчика, нестабильный участок, причина исключения и т.п. В расчётных формулах не участвует. |

Пустые T не заменяются нулями. Ноль °C означает действительное числовое измерение и требует установленного valid. Для запуска нужен хотя бы один достоверный температурный канал в сессии, но полный обход и все 840 значений не обязательны.

«Добавить остановку» дописывает строку с новым индексом и начальным окном 1 с; эти времена — заготовка для редактирования, не измерение. Температуры пустые, все valid сняты. **При ручном заполнении чисел T установите соответствующие valid самостоятельно.** «Удалить выбранные» удаляет строки, содержащие выделенные ячейки. Таблица шире окна — остальные T/флаги/примечание доступны горизонтальной прокруткой. Поддерживается вставка таблиц из Excel.

## 7. Таблица «Давление и газ»: каждая ячейка

Одна строка — один отсчёт одного физического канала. На каждый используемый канал нужны минимум два отсчёта, даже если давление постоянно. Внутри канала время должно строго возрастать, без повторов; приложение не сортирует неупорядоченные записи молча. Топливо и газ могут иметь разные временные сетки.

| Столбец | Что вводить |
|---|---|
| **Коллектор** | Имя канала, совпадающее с привязками форсунок, например `A` или `B`. Для общего газового давления всех коллекторов допускается `*`. Газ конкретного коллектора имеет приоритет над общим `*`. |
| **t, с (сырые часы)** | Время этого отсчёта в секундах часов прибора, до прибавления «Сдвига часов». Для ручного ввода единица всегда секунда; ms/сутки файла переводятся при импорте. |
| **Давление** | Числовое значение в единицах соседней ячейки. Для Δp требуется >0, для абсолютного давления ≥0. У недостоверного отсчёта допустимо пустое значение. |
| **Единицы** | Точное обозначение: `kgf/cm2` (также `кгс/см²`), `bar`, `Pa`, `kPa` или `MPa`. Например, в строке с `Pa` укажите 980665 для перепада 10 кгс/см². |
| **Вид давления** | Один из пяти кодов из таблицы ниже. Он определяет физический смысл, а не подпись графика. |
| **Достоверно** | Флажок пригодности отсчёта давления. Между недостоверными/пустыми соседними отсчётами интерполировать нельзя. Снятие галочки не «пропускает плохую точку с соединением краёв»; оно создаёт недостоверный участок. |
| **reference_id** | Для избыточных топливного и газового давлений — одно и то же непустое имя их общей базы, например `atm_test_01`. Это текстовый идентификатор, не давление и не номер форсунки. Для уже измеренного Δp и абсолютных рядов можно оставить пустым. |
| **Сдвиг часов, с** | Константа перевода часов данного канала в шкалу остановок: `t_общее=t_сырое+сдвиг`. Задайте одинаковые единицы, вид, reference_id и сдвиг для всех строк одного канала. Например, событие в часах давления t=2 соответствует времени протокола t=12 — сдвиг +10 с. Это синхронизация часов, не транспортная задержка. |

| Вид давления | Смысл и необходимые пары |
|---|---|
| `delta_p` | Уже измеренный физический перепад топлива относительно газа. Газ дополнительно не вычитается. |
| `p_fuel_abs` | Абсолютное давление топлива. Требует `p_gas_abs` того же коллектора или газа `*`; Δp=топливо−газ. |
| `p_fuel_gauge` | Избыточное давление топлива. Требует `p_gas_gauge` с тем же непустым reference_id; Δp=топливо−газ. |
| `p_gas_abs` | Абсолютное давление газа для пары с `p_fuel_abs`. |
| `p_gas_gauge` | Избыточное давление газа для пары с `p_fuel_gauge`. |

Для каждого коллектора задаётся один вид топливного ряда и, если нужен, один газовый ряд. Не добавляйте одновременно Δp и p_fuel_abs для одного коллектора. Абсолютное топливо и избыточный газ смешивать нельзя. После вычитания на всём используемом интервале должен получаться положительный Δp.

Нажатие «Добавить отсчёт» создаёт заготовку: общее имя коллектора, t=0, пустое давление, `kgf/cm2`, `delta_p`, достоверность снята. Измените t, значение и при пригодном измерении установите флаг. Новая строка с повторным t=0 не годится для расчёта. «Удалить выбранные» удаляет выбранные строки. При ручной вставке сначала добавьте достаточное число строк: вставка в этой таблице заполняет существующие строки.

## 8. Таблица «Коллекторы / задержки»: каждая ячейка

| Столбец | Что вводить |
|---|---|
| **ID форсунки** | Защищённое значение 1…140. Нельзя менять; 1–70 — наружный ряд, 71–140 — внутренний. Выключенные позиции сохраняют свои ID. |
| **Коллектор (пусто = общий)** | Имя физического коллектора этой форсунки. Пустая ячейка означает «Коллектор по умолчанию» из паспорта. Для B введите `B` только у форсунок, подключённых к B; соответствующий временной ряд должен быть загружен. |
| **Заданная задержка форсунки, с** | Дополнительную неотрицательную задержку этой форсунки. Пусто или 0 — нет индивидуальной добавки. Она суммируется с общей τ, а не заменяет её. |

Каналы T_R1…T_R6 не являются коллекторами. Номер остановки также не назначает коллектор: каждый измеренный участок получает суммарное влияние всех включённых форсунок через их собственные давления и пространственные ядра.

В расширенном JSON возможны точечные добавки `point_delays_s` с ключами `step_id:канал(1…6):nozzle_id`, например `0:1:38`. В таблице отдельной ячейки для них нет; импортированные добавки сохраняются. Полная задержка = общая + форсунки + точечная. Их значения должны быть получены независимо; скорости/время пролёта приложение не определяет.

## 9. Импорт CSV/XLSX: как заполнить окно сопоставления

Файл должен иметь первую строку заголовков. Для XLSX выбирается лист, значения формул должны быть сохранены в файле; приложение не вычисляет Excel-формулы. CSV читается как UTF-8, поддерживаются разделители запятая, точка с запятой и табуляция. При десятичной запятой удобен разделитель `;`. В списках выберите реальные столбцы своего файла — имена не обязаны совпадать с внутренними.

**Остановки:**

- «Индекс остановки» → столбец step_id; «Не задан» создаёт индексы по порядку непустых строк с 0.
- «Угол» → фактический угол сессии; «Не задан» оставляет номинальный расчёт по паспорту.
- «Начало окна / timestamp» → обязательный столбец времени. «Конец окна» → конец усреднения, если он записан.
- Шесть «Температура R…» → соответствующие датчики, шесть «Достоверность R…» → их необязательные флаги. Если столбца флага нет, непустая числовая T считается достоверной, пустая — пропуском.
- «Примечание» → необязательный текстовый столбец.
- «Единица времени в файле» → секунды, миллисекунды, микросекунды или сутки чисел Excel. Начало/конец переводятся в секунды. Календарные строки дат сначала приведите к числовой шкале времени.
- «Длительность после timestamp, с» используется только при отсутствии конца строки. Ноль создаёт явный мгновенный замер (начало=конец); положительное значение создаёт окно этой длительности. Сама длительность всегда в секундах, независимо от единицы времени файла.

**Давление:**

- «Время» и «Значение давления» → обязательные столбцы.
- «Коллектор», «Единицы», «Вид давления», «Общий ноль избыточного давления» → соответствующие столбцы, если они есть. Иначе используются явно выбранные поля «…если нет столбца» в нижней части окна.
- «Достоверность» → необязательный флаг. Без него непустое значение считается достоверным. Для флагов поддержаны, например, 1/0, true/false, да/нет.
- «Единица времени в файле» → единица сырых часов прибора; «Сдвиг часов» задаётся в секундах и прибавляется после перевода единиц.
- Если разные каналы требуют разных сдвигов часов, импортируйте их отдельно с нужным сдвигом либо затем задайте сдвиг в таблице каждого канала.

После импорта давление может отображаться уже в `kgf/cm2`: значения конвертируются, а оригинальные единицы/строки и сопоставления сохраняются в метаданных. Импорт не заполняет неизвестные давления и радиусы. Проверьте паспорт и привязки перед запуском.

## 10. Нижние кнопки и ход расчёта

| Кнопка | Что происходит |
|---|---|
| **Проверить** | Читает текущие входы, проверяет структуру, координаты, T/маски, временное покрытие давления с задержками и физический Δp. Не строит топливное поле и не заменяет прошлый результат. Полный расчёт дополнительно проверяет расходные характеристики и их применимость. |
| **Сохранить сессию в проект** | Проверяет пригодность протокола для включения в проект и записывает его в память проекта. Отсутствие всех достоверных T допустимо для этого сохранения, но не для запуска. Затем **Ctrl+S** или меню сохранения проекта записывает JSON на диск. Undo/Redo отменяет/повторяет включение. |
| **Рассчитать сессию** | Проверяет входы, создаёт расчётный снимок и запускает worker. При той же геометрии повторно использует пространственные влияния K. Рассчитывает расходы во времени, их средние по окнам и q для шести датчиков каждого шага. Не вызывает F5 и не подменяет вкладку 04. |
| **Отменить** | Просит worker остановиться после текущего участка интегрирования. Частичный результат не применяется; предыдущий завершённый результат сохраняется. |
| **Отчёт CSV / XLSX** | Экспортирует завершённый расчётный снимок. Не экспортирует ещё не пересчитанные правки входов. При изменении входов надпись может стать «Отчёт предыдущего снимка». |

Во время worker кнопки/поля изменения входов блокируются; инструкция остаётся доступной. Полоса и текст показывают этапы пространственных влияний и временных окон. Время включает размер сетки, число форсунок, остановок, узлов давления и сложность Q(Δp).

Приложение использует фиксированные геометрические ядра: `q(P,z,t)=Σ G_j(t)·K_j(P,z)`. В режиме `curve` Q(Δp) сразу задаёт абсолютный расход. Для `manual/sectors` исходный расход при его опорном давлении масштабируется отношением Q(Δp)/Q(Δp_ref). Усредняется **Q от меняющегося давления**, а не Q от среднего давления. Недостающая характеристика не заменяется скрытым корневым законом.

## 11. Результаты: что именно показано

При завершении автоматически открывается «Результаты», паспорт сворачивается для освобождения места. Кнопкой «Паспорт и параметры сессии» его можно снова открыть.

| Элемент | Назначение |
|---|---|
| **Вид** | Выбор одного из пяти представлений, описанных ниже. Это просмотр готового снимка; повторный расчёт всей сессии не нужен. |
| **X: Градусы / Номера окружных ячеек** | Меняет X окружных эпюр. Используется система проекта из расчётного снимка: x_ячеек=θ_проекта·N_сетки/360. При сетке 140 шаг равен 2.571428571°. Это координата окружной сетки, **не step_id и не номер форсунки**; она может быть дробной. Если номинальное число остановок и размер расчётной сетки различаются, шкала ячеек относится к сетке. Матрицы по строкам протокола и история времени от этого списка не меняются. |
| **t снимка, с** | Активно для мгновенной матрицы. Задаёт одно общее время в шкале остановок; после ввода подтвердите Enter или завершите редактирование. Это не номер остановки. Время должно покрываться рядами давления либо явным разрешением временной экстраполяции. |
| **Оси…** | Активно для окружных эпюр и истории давления. Настраивает min/max, основные/промежуточные деления, в том числе отдельную ось Y температуры. Изменение масштаба не меняет измерения или q. |

### 11.1. «Окружные эпюры: q и измеренная T»

Шесть графиков соответствуют шести фактическим радиусам. Синяя линия и левая Y — **плотность массового расхода топлива q, кг/(м²·с)**. Оранжевая линия/точки и правая Y — исходная T в °C. Значение q усреднено за окно именно этой остановки. Для мгновенного замера используется значение в timestamp.

q — среднее по консервативной контрольной ячейке, содержащей реальную координату датчика, не расход в математической точке и не площадь самой термопары. Ячейка выбирается по радиальной полосе и ближайшему угловому центру; на радиальной границе — внешняя полоса. Реальные координаты и площадь выбранной ячейки сохраняются в отчёте. Расход через эту ячейку = q·площадь, кг/с.

Графики сортируют копию точек по углу для просмотра. Исходный порядок строк/времён не меняется. Повторный угол в другое время — другое наблюдение; линия может соединять его с тем же X. Для разбора таких случаев обращайтесь к протоколу/отчёту. Недостоверные T дают разрывы, расчёт q в этих координатах сохраняется.

Совпадение пиков q и T — визуальное сопоставление, а не доказательство причинности или качества температурной модели. Сравниваются разные физические величины на разных Y.

### 11.2. «Матрица q по окнам»

Шесть строк — каналы R1…R6. Столбцы идут **в порядке строк протокола**, подписи по X показывают step_id. Цвет — среднее q за собственное окно каждого столбца. Это не одновременно существующее поле: соседние столбцы могут относиться к разным давлениям и временам.

### 11.3. «Измеренная T по окнам»

Тот же порядок каналов/остановок, цвет — измеренная T в °C. Пустые и недостоверные значения маскируются. Интерполяции отсутствующих температур и корректировки инерции датчика нет.

### 11.4. «История давления»

Показывает физический **Δp** каждого топливного коллектора в кгс/см² по общей шкале времени. При абсолютных/избыточных рядах это уже разность топлива и газа, а не исходное давление подачи. Полупрозрачные полосы отмечают окна остановок. Исходные числа подачи/газа можно посмотреть в таблице «Давление и газ» и отчёте.

### 11.5. «Мгновенная матрица τ=0»

Для заданного t строится **полное** расчётное сечение по всей сетке: X — индекс окружной ячейки, Y — радиальный уровень, цвет — q. Это может быть не 6×140, если на вкладке 01 задана другая сетка.

В строке над матрицей: подача через сопла, достигшие плоскости; расход внутри тракта; потери за внутренней/наружной стенками; относительная невязка баланса. Для такого единого времени проверяется `G = внутри + за внутренней + за наружной`. Небольшая численная невязка показывает сохранение массы, но не экспериментальную точность модели.

Полные мгновенные снимки показываются при **τ=0**, даже если для сопоставления окон введены задержки. Они не изображают полное поле с различными точечными задержками. Для составных матриц из разных времён единый мгновенный глобальный баланс не определён, поэтому такой баланс им не присваивается.

### 11.6. Взаимодействие с графиками

На эпюрах и истории давления: наведение — прицел и координаты; двойной ЛКМ — зафиксированная точка на кривой (до 10 на полотне); ЛКМ+ПКМ — очистка точек. Удержание ЛКМ с движением создаёт наклонную вспомогательную прямую с уравнением (до 10 на эпюру); Delete удаляет наклонные прямые. Средняя кнопка с выделением области — zoom; Ctrl+средняя кнопка или R — исходный масштаб; Esc отменяет незавершённый жест. На двух Y координата Y относится к соответствующей кривой/оси. Вспомогательные отметки являются оформлением просмотра и не входят в измерения/JSON сессии.

## 12. Сохранение, повторное открытие и основной расчёт

| Что требуется | Что сделать |
|---|---|
| Сохранить только входную сессию | «JSON: сохранить». При повторной загрузке основной проект должен иметь нужные геометрию и характеристики. |
| Сохранить проект вместе с протоколом | «Сохранить сессию в проект», затем Ctrl+S. Сохраняется текущий основной проект и входная сессия; изменение её входов после включения требует **повторного включения**, затем сохранения проекта. Один Ctrl+S не переносит ещё не включённые правки вкладки 05. |
| Сохранить рассчитанные значения и паспорт расчёта | «Отчёт CSV / XLSX». JSON проекта/сессии не является хранилищем рассчитанных матриц. |
| Восстановить графики после перезапуска | Открыть сохранённый проект/сессию, проверить входы, снова «Рассчитать сессию». |
| Изменить исходные данные и увидеть новый результат | Исправить входы и пересчитать. До успешного завершения виден прошлый снимок; его экспорт также относится к прошлым входам. Отмена/ошибка не подменяет его частичным результатом. |
| Получить стационарное сопоставление на 04 | Для одного общего коллектора вручную задать соответствующий физический перепад и режим пересчёта в настройках 02, выбрать сопоставимые z/сетку и выполнить F5. Сессия не делает этого за пользователя. Составной обход не превращается в стационарное поле одним средним давлением; разные коллекторы также нельзя заменить одним общим Δp без дополнительного допущения. |

Результаты сессии не назначаются автоматически эталоном «Идентификации параметров». Температурные измерения не являются топливным эталоном. Изменения коэффициентов по физически допустимому топливному эталону выполняются отдельно, через идентификацию и её явное применение.

При изменении геометрии/характеристик основного проекта завершённая сессия остаётся прошлым расчётным снимком до пересчёта. Её отчёт сохраняет именно тот проект, по которому она была рассчитана.

## 13. Что входит в отчёт

XLSX содержит листы:

| Лист | Содержание |
|---|---|
| **Measurements** | По строке на канал каждой остановки: step_id, фактические координаты, окно/метод, исходная T и флаг, q, границы/площадь контрольной ячейки и ссылка на строку расходов. Для 140 остановок — 840 строк данных. |
| **Flows** | Средние расходы всех 140 позиций за несдвинутое окно каждой остановки, кг/с; выключенные позиции остаются с нулём. |
| **Pressure_windows** | Коллектор, использованное окно и min/max/mean физического Δp, включая сдвинутые окна при задержках. |
| **Instant_balances** | Балансы полных мгновенных сечений в проверенных временах, включая границы/середины окон и узлы давления. |
| **Raw_pressure** | Ряды давления расчётного снимка, сырые/синхронизированные времена, единицы, качество и reference_id. После импорта значения здесь могут быть уже переведены в kgf/cm2; оригинальные строки файла остаются в метаданных. |
| **Metadata** | JSON-паспорт, предупреждения/методы, снимок проекта и сессии, исходные строки импорта. Длинные записи разделены на нумерованные части. |
| **Delayed_flows** | Добавляется при заданных задержках: фактически использованные средние расходы и задержки для каждой пары «канал/остановка». Их следует использовать для воспроизведения q с задержками; обычный Flows относится к несдвинутому окну. |

При выборе CSV создаётся **несколько файлов рядом**: основной Measurements, дополнительные таблицы с суффиксами, `_manifest.json` и `_session.json`. Сохраняйте комплект целиком. Это отчёт, а не файл для прямого открытия как основной проект. Все значения относятся к завершённому расчётному снимку; исходные входные файлы расчётом не перезаписываются.

## 14. Частые сообщения и порядок оценки результата

| Сообщение/ситуация | Что проверить |
|---|---|
| Нет достоверных температур | Импортированные столбцы T, пустые ячейки и valid. При ручном вводе галочки нужно установить отдельно. |
| Нужны шесть различных радиусов / радиусы вне тракта | Шесть значений через `;`, единицы мм, порядок датчиков и размеры проекта. |
| Время давления должно строго возрастать | Повторы, порядок строк каждого канала, случайно оставленные добавленные строки t=0. |
| Время вне записи / нет покрытия окна | Синхронизацию/единицы времени, сдвиг часов, начало/конец и сумму задержек. Не включайте экстраполяцию вместо исправления ошибочных часов. |
| Недостоверный интервал / большой max_gap | Флаги давления и реальную плотность записи. Приложение не соединяет через недостоверные отсчёты. |
| Нет ряда коллектора | Точное имя в паспорте, таблице форсунок и таблице давления; A/B — разные каналы. |
| Нужен газ / несовместимые базисы | Физический вид топлива/газа и общий reference_id для избыточных рядов. |
| Δp должен быть >0 | Единицы, физические величины, вычитание газа и продолжение ряда при экстраполяции. |
| Нет Q / давление вне диапазона характеристики | Тип распылителя и его Q(Δp), давление независимого измерения расхода/секторов и весь использованный диапазон. |
| Окна перекрываются / end ≤ start | Реальный последовательный протокол. Для мгновенной записи равенство допустимо только с методом instantaneous. |
| T исчезла, но q рассчитано | Снят valid T или T отсутствует. Это ожидаемое поведение; флаг T не выключает топливное поле. |
| Вкладка 04 не изменилась | Ожидаемо: результаты вкладки 05 автоматически в основной расчёт не передаются. |

Сначала оцените корректность входов, часов, координат и давления. Затем проверьте диапазон характеристик, предупреждения отчёта и балансы мгновенных снимков. При необходимости сравните постоянный режим со стационарным расчётом на одинаковой площадке. Лишь после этого интерпретируйте распределения q и измеренной T. Численная точность и закрытый баланс не оценивают погрешность датчиков, точность ядра или наличие физической связи q→T.

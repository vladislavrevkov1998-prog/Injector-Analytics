# Договор о входных данных испытаний (черновик для v0.5)

> Историческое предложение, заменённое уточнением пользователя от 17.10.2026.
> Действующий формат v0.5.2 — давление по N постоянным временным шагам,
> без входных температур и окон усреднения. См. [инструкцию режима](QUASISTATIONARY_GUIDE.md).

Эти таблицы — **предлагаемый** формат импорта; конкретные названия колонок можно отображать через UI mapping, не требовать точных имён у пользователя. В проекте должны храниться физические единицы, источник и флаги качества каждого набора данных.

## Таблица A. Измерения по остановкам (Excel/CSV)

Одна строка = одна окружная остановка гребёнки из шести датчиков.

| Поле | Смысл |
| --- | --- |
| `step_id` | Индекс остановки 0..N-1, **не** номер форсунки |
| `theta_deg` | Реальный измеренный угол, или оставлено пустым при расчёте по заданному шагу |
| `t_start_s`, `t_end_s` | Временное окно считывания всех шести каналов, с привязкой к записи давления |
| `T_R1_C` ... `T_R6_C` | Шесть температур одновременно в данном угловом положении |
| `valid_R1` ... `valid_R6` | Опциональные маски ошибок/отсутствия измерения |
| `note` | Необязательное пояснение |

Число строк обычно 140, но импорт должен разрешать неполный эксперимент. Дополнительно в метаданных: радиусы шести датчиков, координата плоскости z (глобальная), угол начала, шаг 360/140°, направление вращения, время усреднения и способ синхронизации часов.

## Таблица B. Давление как функция времени

| Поле | Смысл |
| --- | --- |
| `t_s` | Время записи давления |
| `manifold_id` | Коллектор, например A (не номер форсунки) |
| `pressure` | Измеренное значение |
| `unit` | кгс/см² / bar / Pa, с явной конверсией |
| `pressure_kind` | `delta_p`, `p_fuel_abs` или `p_fuel_gauge` |
| `quality` | Флаг достоверности, опционально |

Если задано абсолютное/избыточное давление коллектора, потребуется источник давления газа и выбор базиса, иначе перепад не вычислять молча. Поддержать единый массив давления и несколько коллекторов; справочник привязок форсунка→коллектор хранить отдельно.

## Таблица C. Связь с форсунками

Параметры форсунок остаются в JSON проекта: `nozzle_id`, `manifold_id` (будущий), `atomizer_type_id`, эталонный `G_ref`, давление измерения `Δp_ref`, статус источника (`manual/sectors/curve`). Нумерация 1–70 наружный ряд, 71–140 внутренний. Соответствие `measurement step` и `nozzle_id` отсутствует по определению.

## Политика ввода
- Не терять сырые данные; сопоставления времён и единиц — отдельные метаданные.
- Для 6 температур на одном шаге использовать общие t0/t1, если не предоставлены действительные временные смещения по каналам.
- Нельзя преобразовать матрицу измерений `T[6,140]` в «одновременную» температуру только путём перестановки/интерполяции по углу.
- Не обрезать/не экстраполировать давление за временными границами молча.
- На v0.5 `T` используется только для просмотра/сравнения, `q` — для корректировки режима топлива; **отсутствует** формула перевода q→T.

## Пример заголовков CSV

```csv
step_id,theta_deg,t_start_s,t_end_s,T_R1_C,T_R2_C,T_R3_C,T_R4_C,T_R5_C,T_R6_C
0,0.0,1.0,5.0,,
1,2.571428571,6.0,10.0,,
```

Здесь пустые T приведены только для показа формата, **не являются тестовыми физическими данными**; такой неполный файл должен корректно выдавать сообщение об отсутствии температур, а не нули. Для тестов генерировать отдельный синтетический комплект известных чисел.

## Отчёт
Отдельно выводить: номер измерения, угол и радиус, исходную температуру и её статус, окно времени, использованную временную кривую давления, min/max/mean Δp, используемую расходную характеристику каждого типа, усреднённые расходы, вычисленное топливное поле, предупреждения о недостаточности данных/предположениях. Метаданные передавать в экспорт XLSX, CSV и JSON.

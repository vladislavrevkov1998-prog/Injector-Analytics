# Топливные эталоны v0.4

Диалог «Идентификация параметров» работает с усреднёнными значениями на
контрольных ячейках текущей сетки. Данные в точках CFD сначала нужно привести
к таким ячейкам. Направление глобальных углов — против часовой стрелки от +X.
Сектора отдельных форсунок и ID форсунок не являются индексами этих наблюдений.

## Ввод

Поддерживаются:

- JSON-проект Fuel Field Pilot: из него вычисляется топливный эталон, источник
  обозначается `reference_model`; это расчётное поле, а не экспериментальное q.
- JSON `fuel-regression-target-v1`, создаваемый `regression_io.write_target`.
- CSV/XLSX с заголовками ниже. В Excel принимаются листы, содержащие quantity
  и value. Первая строка — заголовки, не произвольная температурная таблица.

| Столбец | Значения / смысл |
| --- | --- |
| quantity | flux / cell_mass / normalized_ring / normalized_track |
| unit | кг/(м²·с) / кг/с / 1 / 1 соответственно |
| source_kind | fuel / synthetic / reference_model |
| z_mm | Глобальное неотрицательное z, мм |
| radius_mm | Физический центр радиальной ячейки, мм |
| theta_deg | Глобальный центр окружной ячейки, градусы |
| value | Наблюдаемая величина в указанных единицах |
| valid | 0/false исключает отсутствующее/недостоверное наблюдение; по умолчанию true |
| weight | Конечный неотрицательный вес, по умолчанию 1; нулевой исключает наблюдение |
| split | train / holdout / test; по умолчанию train |
| area_m2 | Площадь контрольной ячейки; обязательна для cell_mass |

В JSON дополнительно хранится metadata: источник, описание, геометрия,
условия получения и известные параметры синтетического генератора.
Загрузчик добавляет имя файла и SHA256. Для расчётного проекта сохраняются
настройки модели. Физические центры сопоставляются с допуском 10⁻⁷;
неявная интерполяция, изменение направления или нормировка отсутствуют.
При наличии площадей/геометрии проверяется соответствие контрольных областей.
CSV без area_m2 для flux/индексов по контракту описывает именно ячейки текущей
сетки, а не точечный датчик или иной footprint.

Пример:

```csv
quantity,unit,source_kind,z_mm,radius_mm,theta_deg,value,valid,weight,split
flux,кг/(м²·с),synthetic,30,275,0,0.25,true,1,train
flux,кг/(м²·с),synthetic,30,275,2.5714285714285716,0.31,true,1,holdout
```

В режиме normalized_ring/track величина уже должна быть соответствующим
безразмерным индексом. Температурные данные, включая нормированную температуру,
не являются топливной целью. Сравнительная панель продолжает показывать их
независимо, без передачи оптимизатору.

## Подбор

Подбираются выбранные наследуемые параметры cooled/uncooled. Индивидуальные
геометрические overrides сохраняются и не заменяются шаблоном при подгонке.
Параметры без влияния на выбранные наблюдения не предлагаются: например,
alpha/k/угловое затухание при z_local=0, вращение равномерной эпюры или
параметры типа без установленного источника с положительным расходом.

Критерий:

`J = Σ_train w_i (f_i − y_i)² + λ Σ_k ((β_k − β_start,k)/(max_k − min_k))²`.

Для relative ошибки первое слагаемое использует `(f−y)/max(|y|, floor)`.
Floor задаётся пользователем в единицах цели; при почти нулевых y он особенно
важен. По умолчанию абсолютный критерий и λ=0. Начальные значения/bounds,
модели, seed и лимит задаются явно. Прямой расчёт — существующий консервативный
calculate_plane; расходные характеристики и измеренные сектора не подбираются.

Алгоритм — scipy.optimize.least_squares с box constraints. Консервативная
гистограмма кусочно гладкая, поэтому используются конечные шаги по
нормированным диапазонам параметров и предварительный воспроизводимый поиск.
При одном параметре проверяется сетка из 17 кандидатов; при нескольких —
координатные сдвиги и начальная точка, зависящая от seed. Лимит учитывает
прямые расчёты для поиска и численной диагностики; повторные точки кэшируются.

Метрики RMSE/MAE/R² выводятся в физических единицах отдельно для train и
holdout/test (объединённая независимая часть). Holdout не участвует в критерии.
При постоянной цели R² — N/A. Ранг/обусловленность и условная standard_error
из численного Jacobian — диагностические оценки; они не подтверждают
единственность или экспериментальную точность. Нужна сеточная сходимость.

## Применение и восстановление

Диалог получает неизменяемый сериализованный снимок и SHA256. До применения
основной проект не изменяется. Предпросмотр сравнивает выбранный старт с
кандидатом в выбранной модели; исходный проект отдельно сохранён в снимке.
«Применить» — одна операция Undo/Redo. «Вернуть исходное» восстанавливает
канонический снимок полностью, включая дополнительные пользовательские поля.
Если после снимка/применения основной проект изменился, автоматическая замена
блокируется; используйте последовательный Undo либо откройте новый диалог.

Экспорт XLSX: Parameters, Metrics, Residuals, Metadata, Validation. N/A
остаётся явным, начальный и итоговый JSON сохранены частями по 16000 символов,
чтобы не превышать лимит Excel на одну ячейку. В таблице остатков есть
физические z/R/θ, единицы, маски, веса и роль каждого наблюдения.

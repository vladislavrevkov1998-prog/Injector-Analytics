# ROADMAP v0.2 — согласованное ТЗ Fuel Field Pilot

**Базовый код: v0.1.2.** Этот документ — требования, не реализованная программа. Сначала добавить исходную рабочую кодовую базу из Fuel_Field_Pilot_Codex_Handoff_v0.2_spec.zip в корень репозитория, сохранив `src/`, `tests/`, `examples/`, `main.py` и `requirements.txt`.

## Концепция
140 позиций форсунок, два шахматных ряда, 1–70 наружный, 71–140 внутренний. Измеренные 36-секторные эпюры в мл; первый сектор ориентирован по нормали к средней линии кольца, к ней же обращены первые секторы обоих рядов, отсчёт остальных против часовой стрелки со стороны выхода. Форсунки могут отключаться без сдвига соседей. Четыре осевых сечения по z; переменная радиально-окружная матрица, исходно 6×140.

Плотность массового расхода в сечении `q(x,y,z)` [кг/(с·м²)] строится как сумма нормированных индивидуальных полей. Количество топлива в контрольной ячейке — интеграл q по её площади. Выводить потоки, объёмы за заданное время и безразмерные индексы; НЕ называть q концентрацией кг/м³ без скорости капель.

Сохранять баланс: сумма расходов форсунок равна расходу в пределах кольцевого тракта плюс потоки за внутреннюю и внешнюю границы.

## v0.1.3 — быстрый UI и редактирование

1. При переключении z не перерисовывать все неактивные вкладки. Lazy rendering и кеширование, переиспользовать расчётные поля; инвалидация кэша при изменении проекта, сечения или представления. Замерить скорость до/после.
2. Ctrl+Z/Ctrl+Y и стек Undo; вставка одного значения во все выделенные редактируемые ячейки; групповые операции и вставка TSV из Excel.
3. Рядом с таблицей 36 секторов полярная эпюра и кольцевое поле одной выбранной форсунки при z=0. Обновление на каждую правку без пересчёта всех 140 позиций.
4. Шкалы: Auto; Manual (min,max), общая шкала нескольких z по выбору. Manual режимы **Saturate** — крайние цвета для значений вне диапазона и **Clip to range** — прозрачные области вне диапазона. Настройки сохраняются в JSON и не изменяют числовые данные.
5. Читаемые математические формулы и расшифровка величин (Matplotlib MathText).

## v0.2 — модель расходов, распылители, типы

6. Справочник типов распылителей на первой вкладке: ID, имя, тип расходной характеристики, таблица/параметры, ссылки из форсунок; разрешить несколько типов. В каждой форсунке atomizer_type_id. Не удалять тип, на который ссылаются действующие форсунки, без обработки ссылок.
7. **Экспериментальный способ**: произвольное число измеренных пар (Δp,Q), ввод, добавление, изменение и удаление строк, импорт Excel/CSV, график характеристики. Кусочно-линейная интерполяция базово точно проходит по измеренным точкам. Перепады положительные, уникальные, расход неотрицательный; сортировка, проверка NaN/дубликатов. Явное предупреждение при экстраполяции и отсутствие скрытого сглаживания.
8. **Расчётный способ**: гидравлический расчёт центробежного распылителя по **методике Дитякина**. Должен опираться на проверенные уравнения, коэффициенты, исходную геометрию и диапазон применимости. Пока методика не верифицирована — нельзя маркировать базовую формулу `mdot = μ*A*sqrt(2ρΔp)` как Дитякин; её можно использовать отдельно с явной маркировкой упрощённой модели. **Метод Тейлора отложен.**
9. Перепады: 36 секторов измерены при 2.5 кгс/см², расход — отдельно при 30 кгс/см². В каждой форсунке хранить измеренный расход и давление независимо от секторов. При режиме `sectors`: по собранному объёму V за время t и плотности ρ вычислять `mdot_2.5=ρΣV/(t η_capture)`, затем `mdot_target=mdot_2.5 × Q_type(target)/Q_type(2.5)`; полнота сбора η_capture может быть неизвестна (явное допущение). Нельзя перезаписывать независимые значения измеренного расхода. Любая правка сектора/характеристики меняет связанную оценку.
10. Заголовок столбца расхода переключает единицы кг/ч ↔ л/мин, каноническая единица хранения одна; конверсия зависит от плотности. Указываются режим давления, источник и измеренный/расчётный статус.
11. Тип форсунки «охлаждаемая»/«неохлаждаемая», изменяемые шаблоны α, R_сопла, h0, k_linear, k_quadratic, p, z_ref, α_inner/outer, Clock, L_decay, sigma, omega. Индивидуальные override с reset.
12. Заменить пользовательское Rc0 на наружный радиус срывающейся плёнки R_сопла. Начальная жидкая кольцевая зона [R_сопла−h0, R_сопла], исходный Rc0 = R_сопла−h0/2. Миграция старых JSON: R_сопла=Rc0+h0/2.
13. Режимы ручной/автоматической расстановки. При изменении углового положения форсунки в auto-follow смещаются она и последующие форсунки **того же ряда** с сохранением расстояний, другие ряды не менять. Позиции отключённых форсунок остаются при отключении.

## Тесты
- Проверять баланс без потерь при численной нормировке поля; отдельно учитывать выход за стенки.
- Смена единиц/шкалы не влияет на физический результат и экспорт.
- Clip to range делает невидимыми только области вне [min,max], без удаления координат/подписей.
- Пересчёт 2.5→30 проверяется на известной кривой, независимый расход при 30 сохраняется.
- Смена типа распылителя не изменяет исходные 36 объёмов.
- Отключение любой форсунки не сдвигает остальные.
- Инициализация старых JSON сохраняет численные значения в исходной модели.
- Перед выпуском нового архива запускать все unit tests. На Windows в Spyder проверять GUI отдельно.
